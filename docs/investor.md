# Investor note (narrow)

Ask three things only. Everything else is noise until those are clear.

## 1. What is the product?

**Aura** = live FlatAST runtime (query/mutate, stable IDs, concurrency, audit, incr compile).

**aura-build** = the **dev-time room on that floor** — anti-postman worldlines, fiber multi-candidate select-best, trajectory flywheel for RL/specialist distillation, self-evolving memory/harness (L1/L2/L3).

It is **not** another coding agent and **not** a prettier language. Soft integrations ≠ Restricted moat; we deny plugin-as-moat.

## 2. Who pays, and for what?

Pricing sketch (not a commitment):

| Meter | What it prices |
|-------|----------------|
| **Seats** | Humans in the room (policy, review, canary) |
| **Workspace** | Live FlatAST capacity / retention / concurrency ceiling |
| **Mutate** | Billed mutate+eval episodes (worldline fan-out included) |
| **Audit** | Durable audit + trajectory export for compliance / RL pipelines |

Land with dogfood on cybrid-systems/aura; expand to Aura-shaped product repos that need reproducible mutate→eval loops.

## 3. Why can’t this be copied by “just adding an agent”?

**Moat (substance, not plugins):**

- Runtime-native worldlines (stable IDs + incr compile + audit) vs git-worktree mail.
- Trajectory protocol as first-class export — devalues off-runtime “we logged the chat” datasets.
- Harness that mutates itself under canary (L1 strategy code; L2 offline weights; L3 online experimental only).
- Soft ≠ Restricted: openness on surfaces; scarcity on the floor semantics.

### Short answers

**DeepSeek / open models?** Commodity inference helps us; it does not replace a live FlatAST floor or reproducible select-best trajectories.

**Harness?** The product *is* an evolving harness on Aura — not a static prompt pack. L3 online weights stay experimental until canary proves them.

If there is no runtime under the demo, there is no company narrative — only another agent slide.
